# jev-chat-jarvis（macOS）

微信弹出一条消息 → 悬浮窗立刻告诉你**这句话的真实意图**、**风险几级**、**该怎么回**。

**纯只读、零封号风险**——不注入、不 hook、不解密数据库，只是「看屏幕 + 本地模型判断」。

## 它能做什么

- **意图 + 风险**：7 类意图（帮忙/问进度/批评/要解释/闲聊/约时间/夸奖）零样本判断 + 风险 0–9 分级 + 行动建议；判断层跑本地 decider-2b（无 key、不出网，M1 Pro 稳态 ~0.6 s/条），异常时自动兜底到 laya-coreml。设置可选「通用聊天」或「情侣与暧昧」。2026-10-03 实测：关系场景在合成情侣/暧昧调词集上 **29/36 → 31/36**，预先冻结的确认集 **18/20 → 19/20**；通用模式的 54 条学生回归为 **49/54（90.7%）**，兜底 laya-coreml **20/54（37.0%）**。当前回归直接调用应用的意图+风险双槽路径；历史 **53/54（98.1%）** 来自仅意图单槽探针，口径不同。关系模式在学生集为 48/54，因此默认仍是通用判断，不自动推断关系或切换场景。
- **关系信号（离线、可解释）**：在任务意图之外，从当前消息 + 最近上下文里提取字面线索，提示`主动靠近/发出邀约/试探态度/直接表达好感/寻求情绪价值/关系不满/尝试和好/回避降温/边界拒绝/简短回应`等聊天信号；悬停可看命中的原文片段与谨慎解读。尊重否定表达，不把「别再熬夜」当拒绝；简短回复不扣好感分，连续发消息不加好感分，不做性别化断言、不额外调模型、不写日志。
- **候选回复**：内置 13 种话术并发生成，每种各出 2 条 → 先上屏 → 本地模型排序后原位重排；默认「自然关心」+「轻松甜一点」，另可选「认真沟通」，原有话术仍可选。三种关系话术同时适用于情侣与互相了解阶段：不擅自认定恋爱关系，优先回应感受、尊重拒绝和空间，对未核实指责先听清问题；第二条不再强制更皮、更夸张。换话术立刻按当前消息重新生成。
- **快**：消息一出现判断 + 生成同时起跑，M1 Pro 出意图 ~1 s（decider-2b 应用内实测口径）、出候选 ~1.5–2 s（端到端为机制推算口径，以日志实测为准）
- **YOLO 检测框**（可选，`JEV_BOXES=1` 启动即开、菜单栏可切）：OCR 命中的消息实时框在微信窗口上，对方/我分色 + 置信度
- **功耗读数**：聊天名右侧一行瓦数，每秒刷新，**免 root、不装任何特权组件**。口径按能读到的来：电池放电时是整机功耗、插电时是充电功率或 GPU 能量（IOReport 私有能量计数，实测 M2 Pro 空闲 0.1–0.5 W、MPS 满载 23.9 W）；CPU/整机功率只有 `powermetrics`（需 root）才读得到，面板**不显示读不到的数值**，鼠标悬停有口径说明

## 面板读法

面板使用 macOS 原生浅色磨砂材质：顶部是当前聊天、右侧的功耗读数、分析状态、正在处理的消息，以及带说话人标注（我/对方/群成员名）的识别上文——就是本次实际喂给模型的上下文，最多 4 轮，超长单行截断显示。正在处理的消息单独按完整文字换行并增高，悬停也可查看全文；中间依次显示意图、识别率、风险等级和行动建议；底部按话术分组展示候选回复。当前风险圆点会轻微呼吸提示。单聊判断完成后，说话人行会附上非中性的关系信号（如 `关系信号：试探态度`），悬停可看命中的字面线索、谨慎解读和免责声明。每条候选左侧是本地排序概率，右侧仍只有「复制」和「填入」；候选行会随完整文字自动增高，不截断内容，发送始终由用户在微信里手动完成。

功耗读数是唯一和微信无关的一行：`电池 8.4 W` 表示电池正在放电（≈整机功耗），`充电 45.0 W` 是充电速率（**不是**整机功耗），插电且电池无电流时退回显示 `GPU 1.2 W`，什么都读不到就是 `功耗 —`；悬停看当前口径。它每秒采一次（IOReport 差值 ~0.4 ms），暂停或收起面板时照常刷新——这行本来就是给你随时瞄一眼的。

「不用」的话术槽只保留一行下拉选择，不生成也不占候选行；开启或关闭话术只改变面板高度，不改变判断与轮询流程。候选还在路上时（等待判断/生成中/换话术/排序中），候选标题旁有转圈指示，对应话术组里显示「正在生成候选…」占位，第一条流式候选落地占位即退场——预留高度不变，候选到达时面板不跳动。黄色窗口按钮收起到聊天名与状态，红色窗口按钮退出；收起期间迟到的候选不会再把窗口撑开。

## 用法

**只想用**：[Releases](https://github.com/jev-chat/jev-chat-jarvis-mac/releases) 下载 `.app`，解压拖进「应用程序」，**第一次右键 → 打开**（没做公证，双击会被 Gatekeeper 拦）。

首次启动按提示授予「屏幕录制」权限（系统设置 › 隐私与安全性 › 录屏与系统录音，给 **jev-jarvis** 打开），**退出重开**生效；「填入」另需「辅助功能」权限，第一次点会弹系统授权框。v0.3.1 及更早的旧版本还需把 **python3.12** 那条一并打开。

缺少可用的 uv 时，两种启动入口都先完整下载并执行官方安装脚本（下载含超时和重试），失败后尝试已有的 Homebrew。失败提示区分网络、证书、磁盘和安装器错误，详细输出见 `~/Library/Logs/jev-jarvis.log`。官方脚本安装到 `~/.local/bin`，不修改 shell 配置。

**从源码跑**（微信在运行、终端已授予屏幕录制）：`./start.command`。分层自测：

```bash
uv run python src/perception.py                  # 感知层：识别到的消息 + 耗时
uv run python src/judge.py "明天早上能帮我带份早饭不"  # 单条消息出判断（主后端 decider-2b）
uv run python src/judge_laya.py "明天早上能帮我带份早饭不"  # 单条消息出判断（兜底 laya-coreml）
uv run python src/relationship.py "周末有空吗"       # 关系信号规则层（不加载模型、不读屏）
uv run python src/judge_zh_test.py               # 54 条中文意图回归（orig/ab/confirm 分组报分）
uv run python src/generate.py --check            # 生成层凭据解析
uv run python -B -m unittest discover -s tests   # 发出消息/异步结果回归（合成 OCR，不读屏）
uv run python -B probe/ocr_geometry_probe.py     # 合成中文图：Vision 坐标、长短消息、1x/2x 完整性（不读屏）
uv run python probe/bootstrap_regression.py      # 两种启动入口的离线回归；不联网、不实际安装
```

## 配置

判断层**完全本地、无需 key**：decider-2b（torch，首次下载约 7 GB，冷启动 10–20 s 由启动预热兜住，预热万一卡死也只等 30 s 就换兜底出结论，不会一直挂着），异常时自动兜底 laya-coreml（Core ML，首次使用另下模型包）。只有生成层需要 key，打包版内置共享 key，不配也能出候选。全部配置在一个 env 文件（**不提供第二种格式**）：

### 可视化配置（#18）

点击悬浮窗右上角 **齿轮图标（模型设置）**，或菜单栏 **J → 模型设置…**，可编辑 OpenAI 兼容、Anthropic 兼容两组生成密钥、服务地址与模型，以及本地判断的「通用聊天 / 情侣与暧昧」场景。
设置窗口显示在悬浮窗上方，不会被面板遮挡。**保存后必须退出并重新打开应用**；保存不会切换本次运行的配置。

- 窗口编辑 `$XDG_CONFIG_HOME/jev-jarvis/env`（未设置时为 `~/.config/jev-jarvis/env`），显示具体路径。只修改所编辑服务的字段和主动选择的判断场景，保留其他配置、注释和未识别行，文件权限设为 `600`。文件被其他程序修改时拒绝覆盖，需重新打开窗口。
- 填好地址与密钥，点击「获取模型列表」从该服务的 `/models` 接口动态获取，再下拉选择；不内置模型清单。OpenAI/Anthropic 按 `data[].id` 读取。接口不支持、失败或返回空列表时明确提示，仍可手填，不自动换模型或服务。空下拉显示「暂无」（仅作提示，不作为模型保存或调用），仍可手填；底部动态提示以蓝色显示进行状态、绿色显示成功、红色显示错误。列表可见不代表一定有生成权限，选定后再测试。
- 「测试连接」使用窗口内**尚未保存**的地址、密钥和模型发起实际调用，仅发送固定问候语，不读取微信内容；可能产生少量服务费用。生成层必须返回非空文字才算成功，不能用 `--check` 的配置解析成功代替连接成功。
- 密钥掩码显示；窗口仅读取所编辑文件中的值，不把环境变量、项目 `.env` 或内置共享密钥复制进用户文件。各配置页顶部突出显示本次启动正在使用自己的密钥、内置共享密钥或本地判断，以及实际来源；生成页同时标明当前启用的服务，优先级保留在窗口下方。
- 环境变量优先于用户 env，用户 env 优先于项目 `.env`；生成层 OpenAI 组优先于 Anthropic 组，均未配置才使用内置共享密钥。清空当前文件的密钥不会禁用其他来源中的密钥。由终端或启动器导出的值也显示为「环境变量」。
- API 格式由密钥组决定：`OPENAI_*` 使用 OpenAI 格式，`ANTHROPIC_*` 使用 Anthropic 格式；自定义地址不需要包含服务名称。Ollama 可填 `http://localhost:11434/v1`、密钥 `ollama`，模型从本地服务获取或手填。
- 钥匙串：不新增钥匙串读写。如果原 env 用 `$(security find-generic-password …)` 等 shell 表达式提供密钥，窗口不执行表达式、不展示其内容，未输入新密钥时保留原行；仍由已有启动器执行。要在窗口测试该服务，需明确输入密钥；保存将用输入值替换原表达式。外部注入的密钥继续遵循环境变量优先级。
- `JEV_BOXES`、`JEV_TONES`、`OPENAI_EXTRA_BODY` 暂仍通过 env 配置，保存窗口不会改动它们。OpenAI 连接测试沿用当前启动的 `OPENAI_EXTRA_BODY`；完整话术管理等留待后续扩展。

也可继续手动编辑：

```bash
mkdir -p ~/.config/jev-jarvis
cat > ~/.config/jev-jarvis/env <<'ENV'
# 判断层完全本地，无需配置；兜底模型包默认 aac6fef/laya-multilingual-coreml
# export LAYA_COREML_MODEL="aac6fef/laya-multilingual-coreml"

# 生成层：任意 OpenAI 兼容端点
export OPENAI_API_KEY="sk-你的key"
export OPENAI_BASE_URL="https://api.deepseek.com"
export OPENAI_MODEL="deepseek-chat"
# 端点的思考模式要靠额外字段关时填（Qwen3 这类不关会慢几十倍）
# export OPENAI_EXTRA_BODY='{"enable_thinking":false}'
ENV
chmod 600 ~/.config/jev-jarvis/env
```

- **凭据解析以 key 为准**：提供 key 的来源同时决定端点和模型。实测可用：DeepSeek `deepseek-chat`（最快）；智谱 `glm-4-flash`（换 `ANTHROPIC_API_KEY`/`ANTHROPIC_BASE_URL`/`ANTHROPIC_MODEL`，两组都填 OpenAI 组优先）；本地 Ollama `qwen2.5:7b`（完全不出网）
- **别用 thinking 模型**：思考吃光 `max_tokens`，候选 0 条，面板只报「候选生成失败」——DeepSeek 认准 `deepseek-chat`
- **自定义话术**：env 加一行 `JEV_TONES`（`|` 分隔、每条「名字=说明」，同名覆盖内置，重启生效），如 `摸鱼大师=像资深摸鱼选手，把活推得漂亮又不失礼`；说明写清「什么语气 + 别变成什么」最管用
- **情侣与暧昧聊天**：点击齿轮，在「判断场景」选择「情侣与暧昧」，保存并重启即可启用专用意图问句；也可在同一份 env 中写 `JEV_CHAT_SCENE=relationship`（`general` 为通用，未配置或无效值回落通用）。主判断与本地兜底使用同一场景，保存不修改当前会话。默认两种关系话术适合日常关心与轻松互动；遇到不满、争执或需要讲清边界，可以切到「认真沟通」。意图中的「闲聊」仍包含想念、倾诉、关系态度与简短确认，不代表不重要；行动建议改为接住具体感受、温和确认，收到批评也不默认认错。生成原则约束不补写位置、经历、过错和已完成的行为，但候选仍需自己核对后手动发送。
- 自查凭据（不打印完整 key）：`uv run python src/generate.py --check`

## 磁盘占用与清理

判断层模型跟着**启动方式**走：源码跑（`./start.command`、`uv run python src/judge.py` 等）默认放进仓库的 `.models/`，已加 .gitignore、不会进 git 也不会打进 release；`.app` 用户没有「仓库」，仍用用户级缓存。想改位置就在 env 里自己设 `HF_HOME` / `LAYA_COREML_CACHE`（设了就不覆盖）。

| 内容 | 位置 | 大小 | 清理 |
|---|---|---|---|
| 判断层主模型 `decider-2b`（首次启动判断层时下载，判断+排序共用） | 源码跑 `<项目>/.models/hub/models--Mapika--decider-2b`；`.app` `~/.cache/huggingface/hub/models--Mapika--decider-2b` | 3.76 GB / 个 revision（HF 不会自动删旧 revision，实测两个并存 = 7.5 GB） | `rm -rf .models/hub/models--Mapika--decider-2b`（或对应 `~/.cache` 路径）；之后走本地判断会重新下载 |
| 判断层兜底模型 laya-coreml（仅兜底触发时才下载，判断+排序共用） | 同上目录下的 `models--aac6fef--laya-multilingual-coreml`，编译包在 `<项目>/.models/laya-coreml`（`.app` 为 `~/.cache/laya-coreml`） | 模型 0.68 GB + 编译包 ~0.86 GB | 删这两处；之后兜底会重新下载并重新编译 |
| Python 运行环境（venv） | 源码跑仓库 `.venv/`；`.app` `~/Library/Application Support/jev-jarvis/venv` | ~0.7 GB | 删除 .app 不会连带删它，需手动删 |

**换过位置的话旧的那份不会自动清**（用户级缓存 → `.models/` 各一份就翻倍）。想把已经下好的搬进项目、不重新下载：

```bash
ditto ~/.cache/huggingface/hub .models/hub        # 合并进已有目录，保留 HF 的软链/分块布局
HF_HUB_OFFLINE=1 uv run python src/judge.py "周六下午图书馆自习走不走"   # 断网能跑就说明搬对了
```

搬完确认没问题，旧的用户级那份可以按 HF 自己的方式回收（别手删 `models--*`，真实占用在共享 blob 里）：

```bash
.venv/bin/hf cache rm Mapika/decider-2b                       # 连它独占的 blob 一起删
.venv/bin/hf cache rm aac6fef/laya-multilingual-coreml
.venv/bin/hf cache prune                                      # 清旧 revision 与半截下载（实测可回收 3.8 GB）
```

**可选：下载镜像**（国内拉 7.5 GB 会快很多，默认仍走官方端点）。写进 `~/.config/jev-jarvis/env`，两种启动方式都会读：

```bash
HF_ENDPOINT=https://hf-mirror.com
```

生成层配 Ollama 的话模型在 Ollama 自己的目录（`~/.ollama`），非本项目下载。

## 已知限制

- 收发方向靠文字位置判断：横跨左右或居中、无法确认方向的文本标「方向未确认」，**不作为回复目标**（很宽的对方消息可能被跳过）；只有明确识别为「对方」的消息才触发判断与生成，只有自己消息时面板显示「等待可确认的对方消息…」
- 图片/表情包读不出内容；引用回复当普通文本；公众号卡片可能被当消息解读；微信全屏布局下识别可能失效（布局常量待动态化，见 #17）
- OCR 正文中的「搜索」「发送」「输入文字」等词不会按界面噪声整行丢弃。昵称识别结合窗口点尺寸与后续正文间距，多行拼接按实际行高判断间距，避免拉高窗口后吞掉短消息；单独的小字不再仅凭框高删除，图片上方的孤立昵称可能被当成文字消息。字体、气泡边界和收发方向仍是启发式，不能保证每个字都识别正确，也不靠模型猜字补正文。
- 关系信号是基于词面线索的规则层，不是读心或概率；反讽、表情包、上下文缺失、OCR 漏字和关系阶段都会让它失真，只用于提醒你多看一步，不要当结论。群聊里发言人不固定，这层看单聊上下文才有意义。
- 情侣意图用例均为合成文本、人工约定标签，分为 36 条调词用例和预先冻结的 20 条确认用例；不能当作真实聊天总体准确率。可用 `HF_HUB_OFFLINE=1 uv run python -B probe/couple_prompt_ab.py --variants baseline,shipped --confirm` 对比；`tests/test_couple_chat.py` 检查规则边界与生成请求，`probe/couple_generate_smoke.py` 会用三条合成消息调用当前生成服务，检查 18 条候选的结构，语义仍需人工审阅。风险刻度未改，也没有新增风险准确率结论。
- 微信改版会让布局常量失效（`src/perception.py` 顶部常量需重新校准）；多窗口优先识别主窗口「微信 / WeChat」
- 启动后第一条判断慢是正常现象（本地模型预热；预热异常时最多等 30 s 就走兜底，不会分钟级无响应）；不对劲先看日志（分阶段耗时、**不含消息正文**，可放心贴 issue）：`tail -40 ~/Library/Logs/jev-jarvis.log`
- 功耗读数只能读到免 root 那部分：**CPU/整机功耗需要 root（`powermetrics`）**，本项目不加特权组件、不弹授权，所以那个数字不显示；Intel Mac 或读不到能量的机型会一直显示 `功耗 —`（悬停会说明）。电池功率 = 电压×电流，插电且电池电流≈0 时它说明不了整机功耗，面板会退回 GPU 能量而不是给你一个假的 0 W

## 输入区检测框与填入

菜单栏「YOLO 检测框」同时显示消息框和输入目标，约每秒刷新：蓝色实线表示辅助功能接口定位到的输入控件，橙色虚线表示从截图边界推测的输入区；无法定位时显示原因。虚线不代表已取得可写控件，也不修复 #17 的聊天区域固定比例问题。

「填入」优先通过辅助功能接口写入并读回确认。部分微信版本不提供输入控件时，显式点击「填入」会尝试视觉兼容路径：复核窗口、输入区和标题，激活微信、点击输入区、输入文字，再用 OCR 核对。该路径需要屏幕录制及辅助功能权限，会移动鼠标；填入期间请勿操作键鼠或切换聊天。不会自动按发送键，也不使用剪贴板或 Cmd+V；换行和制表符转换为空格。

兼容路径读到已有草稿时停止，提示使用「复制」手动插入；辅助功能路径仍追加原有文字。窗口、焦点或会话变化时停止，画面无法确认时提示检查草稿，不自动重试。视觉边界及 OCR 都可能误判，标题检查也不是会话 ID，不能消除用户同时操作时的竞争；深色主题、多显示器与其他微信版本仍需更多验证。
