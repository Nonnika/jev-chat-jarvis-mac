# 情侣与暧昧场景验证（2026-10-03）

设置里的「判断场景 → 情侣与暧昧」启用专用问句，保存并重启生效；也可在现有 env 写 `JEV_CHAT_SCENE=relationship`。判断仍用本地 decider-2b，7 个意图标签的描述与风险刻度未改。

用例是人工编写的合成微信文本，金标表示可观察的聊天行为，不表示对方的真实好感。36 条调词用例和 20 条确认用例在实验前写好，确认集只用于最后确认；原有学生确认集也没有用于调词。测量直接调用 `Judge.judge()` 的意图+风险双槽路径，包含用例自带的最近上下文。最终还通过实际场景选择路径复验。

| 用例组 | 原通用问句 | 情侣与暧昧问句 |
| --- | --- | --- |
| 情侣/暧昧调词集 | 29/36（80.6%） | 31/36（86.1%） |
| 情侣/暧昧确认集 | 18/20（90.0%） | 19/20（95.0%） |
| 学生 orig | 18/19 | 18/19 |
| 学生 ab | 19/21 | 19/21 |
| 学生 confirm | 12/14 | 11/14 |

专用问句改善了明确的不满和夸奖，但学生确认集少对一条，所以作为显式场景选项，默认通用判断继续沿用原问句。这里的 95% 只指 20 条合成确认用例，不是实际用户聊天的总体准确率，也没有给兜底模型或风险分提供同样的准确率证明。

历史 53/54（98.1%）来自意图单槽探针；当前 `judge_zh_test.py` 已统一到应用调用路径，本机通用 decider 为 49/54（90.7%），laya-coreml 为 20/54（37.0%）。这两个测量口径需分别记录。环境：Apple MPS、torch 2.14.0、transformers 5.17.0、laya-coreml 0.1.0。

关系规则回归覆盖关心与拒绝的区别、否定表达、情绪倾诉、明确不满、道歉和简短确认。短回复不减好感分，连续消息不加好感分；每个字面命中附原文片段供悬停核对。回复新增「自然关心」「轻松甜一点」「认真沟通」，争执时先听清问题，不要求无条件认错；仍由用户核对和手动发送。

完整离线套件通过 93 项测试；设置和悬浮窗用临时配置、合成数据离屏渲染并核对。生成冒烟用安慰、明确边界和矛盾三条合成消息调用当前配置的服务：18 条候选全部非空、每组两条且每条不超过 30 字；人工审阅最终回复的边界与事实依据。结构检查不是回复语义准确率证明。

剩余误判包括「抱抱我嘛」「你到家了吗」「好呀」及「能陪我练一下明天的面试吗」，主要仍是情绪表达、明确请求、状态关心和邀约之间的边界。下一轮应增加新的、未参与本轮调词的真实场景标注；已用过的确认集只能当回归。关系规则还不能可靠处理所有否定范围、引用和反讽，风险分的刻度也未校准。
